# Release-candidate gate

Phase 10 is verification-only. `make rc-gate` records commit, host preflight, Compose output and one machine-readable status per mandatory live gate under `evidence/product-v1/rc/`. Phase 10B/10C uses `make rc-live-gate`; set `RAGOPS_RC_GATES=postgresql,redis_worker,qdrant` to rerun selected gates without deleting previous evidence. The Qdrant gate is also directly runnable with `make test-qdrant-integration`; it bootstraps only the isolated `rc-qdrant` service and its own ephemeral collection. A gate is `PASS` only after execution on an authorized host; unavailable Docker, PostgreSQL, Redis, Qdrant, OIDC or provider services remain `BLOCKED`. No RC tag is created while any mandatory gate is blocked.

The `tenant_isolation` gate (`scripts/tenant_isolation_gate.py`, run with `RAGOPS_RC_GATES=tenant_isolation make rc-live-gate`) creates two unique synthetic `rc-ti-*` tenants in the isolated `ragops_test_*` database from `RAGOPS_TEST_DATABASE_URL`, uses the RC Redis service with its own queue key and a disposable RC Qdrant service, and drives the real FastAPI routes with an ephemeral RS256 issuer through `OIDCIdentityProvider`; live Keycloak token issuance stays covered by the `oidc` gate. Every cross-tenant read, write and mutation must fail with the product's denial, and each path has a same-tenant positive control. `PASS` requires `tenant_leakage = 0`, `vector_tenant_leakage = 0` and a cleanup that removes only the gate's own tenants while leaving all other rows unchanged.

Copy [.env.integration.example](../.env.integration.example) outside the repository, fill secrets manually, and set `RAGOPS_ALLOW_PAID_INTEGRATION_TESTS=1` only for an intentionally bounded paid-provider test.

The `model_router` gate (`scripts/model_router_gate.py`, run with `RAGOPS_RC_GATES=model_router make rc-live-gate`) drives the real `LLMModelRouter` and the real admin routing API with ephemeral OIDC tokens. Only the final provider invoke is a local fake; all outbound HTTP is counted and blocked, so `PASS` requires `paid_provider_calls = 0` and `router_tenant_leakage = 0`. It needs no database because routing policy and catalog are in-process state, and it records the shared-catalog governance risk (`cross_tenant_catalog_influence`) separately.

The `finops` gate (`scripts/finops_gate.py`, run with `RAGOPS_RC_GATES=finops make rc-live-gate`) migrates the isolated `ragops_test_*` database from `RAGOPS_TEST_DATABASE_URL` and drives the real budget, reservation, usage, forecast and alert services for three unique `rc-fo-*` tenants, with independent read-back in fresh sessions. It covers the ALLOW/WARNING/ROUTE_CHEAPER/DENY boundaries, the reserve/commit/release/expire lifecycle, Decimal accounting, duplicate-billing protection and tenant isolation, and re-asserts the PostgreSQL 6 + 6 against 10 reservation race. `PASS` requires `paid_provider_calls = 0`, `finops_tenant_leakage = 0`, `invariant_within_hard_limit = true` and a cleanup that leaves other rows unchanged.

The `rate_limiting` gate (`scripts/rate_limiting_gate.py`, run with `RAGOPS_RC_GATES=rate_limiting make rc-live-gate`) resolves Redis like the `redis_worker` gate (`RAGOPS_REDIS_URL` or the published `rc-redis` port) and uses a unique `ragops:rc:rate-limit:<run-id>` prefix. It proves the below/at/over-capacity boundary, TTL and reset, 25 concurrent requests against a limit of 10 across two limiter instances, tenant, user, route and delimiter isolation, pseudonymized keys, the real `/v1/query` route with 429/Retry-After/RateLimit headers before any provider call, spoofing resistance, the fail-closed 503 on an unreachable limiter and recovery. It deletes only keys under its prefix and verifies that an unrelated sentinel key is unchanged.

The `backup_restore` gate (`scripts/backup_restore_gate.py`, run with `RAGOPS_RC_GATES=backup_restore make rc-live-gate`) uses `RAGOPS_TEST_DATABASE_URL` or the local compose credentials, creates its own `ragops_test_br_{src,dst,neg}_<run>` databases and a disposable RC Qdrant service, seeds two synthetic tenants through the production services, and proves an encrypted backup through an independent validation, rejection of tampered, truncated, incomplete, re-versioned and wrong-key artifacts and of unsafe targets before any mutation, a safe interrupted restore, an exact fresh-target restore with per-tenant digests, and unchanged unrelated PostgreSQL, Qdrant and file sentinels. It drops only its own databases and collections and retains no artifacts.

The `readiness_failure_recovery` gate (`scripts/readiness_failure_recovery_gate.py`, run with `RAGOPS_RC_GATES=readiness_failure_recovery make rc-live-gate`) creates its own `ragops_test_rfr_<run>` database, uses a unique namespace on the RC Redis service and a disposable RC Qdrant service, and reaches each of them only through a loopback fault proxy (`scripts/fault_proxy.py`). Failures are therefore injected for the gate's own API and worker alone; shared services are never stopped or reconfigured. One API instance and one worker runtime live through refusal, blackhole and mid-operation disconnects of PostgreSQL, Redis and Qdrant, the retry budget, a combined outage, startup while unready, unready-first shutdown and a restart that recovers an in-flight message. `PASS` requires `/health` to stay live, `/ready` to fail closed with sanitized reasons and recover without a restart, bounded request failures, `lost_jobs = 0`, no duplicate effects or partial active versions, no busy loop, `readiness_recovery_tenant_leakage = 0`, `paid_provider_calls = 0`, unchanged unrelated PostgreSQL, Redis, Qdrant and file sentinels, and a cleanup of the gate database and Redis keys.

The `browser_e2e` gate (`scripts/browser_e2e_gate.py`, run with `RAGOPS_RC_GATES=browser_e2e make rc-live-gate` after `make e2e-setup`) drives a real headless Chromium (Playwright, pinned build) through the live Streamlit dashboard. The browser follows the real redirect to the local Keycloak realm and types into its login form; the dashboard, API and worker run as real processes on gate-owned loopback ports against a gate-owned `ragops_test_e2e_<run>` database, a gate-owned Redis namespace and a disposable RC Qdrant service. The gate creates its own Keycloak client and synthetic users for two tenants and three roles and removes them afterwards. It covers login, reload, logout with back navigation, token expiry and re-login, wrong password, forged callbacks and an unreachable identity provider; role denial in the UI and at the API; tenant isolation and spoofing through URL, header and body; upload, duplicate submit, rejected files, a queue outage with readiness and recovery, retry; rate limiting; keyboard, desktop and mobile layouts and axe. `PASS` requires `browser_e2e_tenant_leakage = 0`, `paid_provider_calls = 0`, no unexpected page, console or network errors, no credentials in any artifact, and a cleanup that leaves unrelated PostgreSQL, Redis, Keycloak and files unchanged. The Copilot still answers from the local demo corpus, so the evidence records `browser_query_uses_qdrant = false`.

The `oidc` gate obtains its token through the local-only Keycloak client `ragops-integration-check`; the product client `ragops-api` has no password grant. `make oidc-integration-bootstrap` writes a redacted, owner-only snapshot of the realm configuration before it changes anything, verifies `ragops-api.directAccessGrantsEnabled = false` and `ragops-integration-check.directAccessGrantsEnabled = true`, and aborts if anything it does not manage changed. `make oidc-integration-cleanup` removes the gate-only client and the snapshot again. When `KEYCLOAK_ADMIN_PASSWORD` is set, the RC runner performs bootstrap, check and cleanup itself and reports a failed cleanup as `FAIL`.

The `security` gate (`scripts/security_gate.py`, run with `RAGOPS_RC_GATES=security make rc-live-gate` or `make security-gate`) is an evidence orchestrator and always runs last. It runs the regression tests named in the control matrix of [THREAT_MODEL.md](THREAT_MODEL.md) once, performs read-only checks of the proxy, Compose, dependency and Git configuration, reads the settings of the local Keycloak realm, and evaluates the evidence the other gates wrote in the same run. It sends no test inputs of its own. `PASS` requires every mandatory control to have present, well-formed evidence for the tested commit that is at most 24 hours old and true, no uncommitted product changes, no remaining gate-only objects and no credential in the evidence. Missing, malformed or stale evidence is `BLOCKED`; a failed test, a false field, a failed cleanup or a redaction failure is `FAIL`. Because live evidence must match the tested commit, the gates it depends on (`docker_compose`, `oidc`, `tenant_isolation`, `model_router`, `rate_limiting`, `backup_restore`, `readiness_failure_recovery`, `browser_e2e`, `rag_query`, `query_idempotency`, `reservation_reconciliation`, `ocr_ingestion`) have to be run on that commit first.

The `rag_query` gate (`scripts/rag_query_gate.py`, run with `RAGOPS_RC_GATES=rag_query make rc-live-gate` after `make e2e-setup`) is a mandatory gate and proves the productive RAG chain as one composition. It reuses the browser gate's environment in `RAGOPS_QUERY_MODE=vector`: real API and worker processes with an empty data directory (no demo corpus), real Keycloak tokens, a gate-owned `ragops_test_e2e_<run>` database, a gate-owned Redis namespace and a disposable Qdrant service that the API reaches only through a counting proxy. For two tenants it provisions users, the deterministic model and budgets, uploads one document each through `/v1/documents/upload`, waits for the worker and checks the stored chunks in Qdrant, then asks `/v1/query` (top_k 3, the SIMPLE routing class of the deterministic model) and follows every answer through citations, audit events, the usage record and the committed reservation. Per-run markers in the documents are matched against the cited chunks; evidence holds only digests and counts. It also proves zero-result abstention without provider or accounting, an injected accounting failure (a gate-owned database trigger) that returns 503 without the answer and keeps the reservation, a hard budget limit (429 before the provider), a negative control without the tenant's vectors, a Qdrant outage (503) and a browser journey on the vector path (login, upload, indexing, cited answer, no leakage to the other tenant). The gate needs at least 3.5 GiB of available memory before it starts. `PASS` requires zero tenant, vector, citation, usage and budget leakage, at least one observed Qdrant request, no demo retrieval, `paid_provider_calls = 0` and a complete cleanup; the security gate validates the evidence as control LIVE-10.

The `query_idempotency` gate (`scripts/query_idempotency_gate.py`, run with `RAGOPS_RC_GATES=query_idempotency make rc-live-gate`) is the 17th mandatory gate and proves same-key retries of `/v1/query` on the real API and PostgreSQL. It serves the FastAPI application over loopback HTTP in vector mode against a gate-owned `ragops_test_idem_<run>` database migrated to head, with tokens of an ephemeral RS256 issuer and a per-run HMAC secret for the key digest, the unchanged budget reservation, usage booking and idempotency store, and the local deterministic provider (counted per tenant; one tenant is made to time out). With one isolated tenant per scenario it proves a successful replay (one provider call, reservation and usage record, the same `correlation_id`, `Idempotency-Replayed: true`), a conflicting payload (409 before any side effect), the same raw key in another tenant and for another user (independent executions), a zero-result replay without provider or accounting, ten concurrent duplicates (at most one provider call, reservation and usage record, one record), an accounting failure after provider success (a gate-owned trigger; retries answer 409 and never call the provider again), an ambiguous provider timeout (the same) and a failing idempotency store (503 before the provider). It checks that no raw key reaches the database or the audit log and that the stored key digests are the server-keyed HMAC, never a plain SHA-256 of a key, drops its database and temporary files and verifies that the other databases and the repository audit file are unchanged. Evidence holds counts, states and digests only. `PASS` requires all of this with `paid_provider_calls = 0`; the security gate validates the evidence as control LIVE-11.

The `reservation_reconciliation` gate (`scripts/reservation_reconciliation_gate.py`, run with `RAGOPS_RC_GATES=reservation_reconciliation make rc-live-gate`) is the 18th mandatory gate and proves ENT-11.6 reservation reconciliation on the real API and PostgreSQL. Like the idempotency gate it serves the FastAPI application over loopback HTTP in vector mode against a gate-owned `ragops_test_recon_<run>` database migrated to head, with the local deterministic provider counted per tenant; while reconciliation runs the provider refuses and counts every call. Failures are injected only through gate-owned triggers on that database. With one isolated tenant per scenario it proves an undisturbed query (ledger `accounted`, nothing to reconcile), an accounting failure after provider success recovered from the durable receipt (one provider call before, none during, usage 0 → 1, reservation `reserved` → `committed`, the key then replays the settled 409), a lost provider-boundary marker (no provider call, released by reconciliation, recovered by the same key), a provider timeout and unreported usage that stay held for review, usage that already exists (committed, no duplicate), ten concurrent reconcilers of one case (one settlement, one usage record), a reconciliation datastore failure (unchanged state), cross-tenant probing with reservation, ledger and correlation ids (not found) and an ENT-11.5 hold without ledger evidence (never released). It also runs the operator CLI. Evidence holds counts, states and classifications only and names a failure class (`DB_FAILURE`, `TENANT_SCOPE_FAILURE`, `EVIDENCE_MISMATCH`, `UNKNOWN_BILLING`, `DUPLICATE_USAGE`, `DUPLICATE_SETTLEMENT`, `PROVIDER_REPLAY_ATTEMPT`, `INVALID_STATE`, `CLEANUP_FAILURE`, `RESOURCE_BLOCKED`, `UNDETERMINED`) when it fails. `PASS` requires all of this with `paid_provider_calls = 0` and a complete cleanup; the security gate validates the evidence as control LIVE-12.

The `ocr_ingestion` gate (`scripts/ocr_ingestion_gate.py`, run with `RAGOPS_RC_GATES=ocr_ingestion make rc-live-gate`) is the 19th mandatory gate and proves ENT-11.7 OCR ingestion on the real API, worker, PostgreSQL, Redis and a disposable Qdrant in vector mode, with the locally installed Tesseract engine (`deu+eng`) and poppler. Without the engine or its language data the gate is `BLOCKED` with `dependency_status = DEPENDENCY_BLOCKED`; it never substitutes scripted OCR. Wholly synthetic documents are uploaded through the authenticated API: an image-only scanned PDF, a native-text PDF, a mixed PDF (native, scanned and mixed-content pages), an EXIF-rotated JPEG and a PNG. It checks the per-page routes in the page report, the recognized text against a declared accuracy criterion (every exact token — dates, amounts, umlauts and a per-run reference number — verbatim, and a difflib similarity of at least 0.90), page numbers, `page-normalized-v1` boxes, chunk provenance, embeddings and Qdrant points, and that `/v1/query` cites the original page. Retrieval uses fixed questions without the per-run numbers (`fixed-questions-v1`, top_k 1): before each question the gate asserts on the tenant's stored Qdrant vectors that the expected chunk of the target page ranks first with a cosine margin of at least 0.05 and that a direct tenant-filtered Qdrant search returns it first; `/v1/query` must then cite exactly that chunk with its document, version and original page. Negative controls cover a corrupt image, an oversized file (application limit and route limit), an image bomb, unreadable noise (review required, nothing indexed), a real OCR timeout, visually injected instructions (recognized but never followed), a Qdrant outage and a foreign tenant (404 for page reports and regions, no citations). Evidence holds counts, routes, similarity ratios and timings (OCR milliseconds per page, pages per minute, end-to-end latency, peak resident memory of the worker and its OCR subprocesses) — never document or recognized text. `PASS` requires all of this with `paid_provider_calls = 0` and a complete cleanup; the security gate validates the evidence as control LIVE-13.

The `document_intelligence` gate (`scripts/document_intelligence_gate.py`, run with `RAGOPS_RC_GATES=document_intelligence make rc-live-gate`) is the 20th mandatory gate and proves ENT-11.8 document intelligence (ADR 0019) on the real API, worker, PostgreSQL, Redis and a disposable Qdrant, with the locally installed Tesseract engine; without it the gate is `BLOCKED` (`DEPENDENCY_BLOCKED`). The sixteen letters of the frozen synthetic corpus (`scripts/intelligence_fixtures.py`, digest pinned by a test) are uploaded through the authenticated API — two of them as image-only scans read by real OCR — together with a degraded scan, a two-page statement, a letter that claims another creditor's invoice number and, for tenant B, a copy of one letter. The worker extracts, indexes and analyses each version in its own transaction with the deterministic offline extractor `rules-de-v1`; the gate then uses only `/v1/intelligence` and compares every answer with the corpus annotations: classes, creditors (never the collection agency), debtors per person (exact configured aliases only; the shared-address letter stays ambiguous, a similar name stays unmatched), amount types, dates and references, forbidden facts (no enforceable title from a court notice, no dispute from an objection notice, nothing from injected instructions), pages including page 2 of the statement, native and OCR provenance (span, chunk, line box), conservative claim groups (the invoice, reminder and collection letter of one claim are one group whose potentially current amount is the latest stated total, never the naive sum; equal amounts of different claims and the poisoned invoice number stay separate; the tenant summary stays partial while an amount-bearing document has no claim identifier), the paid claim (settled, zero), the review workflow (corrections beside the immutable source fact, one winner among ten concurrent corrections, stale versions 409), idempotent reprocessing of three documents through the worker (identical facts, classifications and groups), the degraded scan (analysed, every fact review-required, in no claim), structured search, tenant isolation, roles and access levels (401 without a token, 403 for writes without the reviewer role, 404 above the access level), forged sources and fabricated amounts (422), alias collisions (409) and that `/v1/query` still answers on the unchanged vector path. Evidence holds booleans, counts, letter keys, fact types and the offline precision/recall report of the design corpus and the held-out letters — never document text, names, amounts or references. `PASS` requires all of this with zero wrong debtors, zero false claim merges, zero leakage, `paid_provider_calls = 0` and a complete cleanup; the security gate validates the evidence as control LIVE-14.

The `web_e2e` gate (`scripts/web_e2e_gate.py`, run with `RAGOPS_RC_GATES=web_e2e make rc-live-gate` after `npm ci` in `apps/web` and `make e2e-setup`) is the 21st mandatory gate and proves the ENT-12-UI web frontend (ADR 0020, [WEB_FRONTEND.md](WEB_FRONTEND.md)) on the real stack. It builds the Next.js production bundle, starts it with `next start` on gate-owned loopback ports (a normal instance, one with a 60-second idle limit and one whose identity provider is unreachable) and reuses the browser gate environment: a gate-owned `ragops_test_e2e_<run>` database, Redis namespace, disposable Qdrant, API and worker on the vector query path, and temporary Keycloak users and client (PKCE S256 enforced on that client) that are removed afterwards. A real headless Chromium signs in through the Keycloak form and covers: security headers (nonce CSP, frame denial, `no-store`), the hardened `__Host-` session cookie, no token in cookies, storage, page or API responses and none in the web server logs, CSRF (missing token, foreign origin), the BFF allowlist, client tenant parameters and forged `Authorization` headers being ignored, DE/EN switching that keeps tenant and session, persists after reload and across navigation, a person profile and a synthetic upload created through the UI, an OCR page report, document intelligence with source provenance shown untranslated, a confirmed review persisted with its version and a stale review answered with the 409 conflict view, the legal notice on claims in both languages, a cited copilot answer with one idempotency key per question and an inert hostile question, viewer denial (navigation, pages, API) and tenant isolation (list and direct access), idle session expiry with re-sign-in, logout that also ends the provider session, the unreachable identity provider message, keyboard skip link and mobile menu, axe-core with the WCAG 2.0/2.1/2.2 A/AA rule tags on every page in both languages (desktop and mobile) and horizontal overflow at tablet and mobile widths, plus screenshots in both languages. The `privacy_egress` gate (`scripts/privacy_egress_gate.py`, run with `RAGOPS_RC_GATES=privacy_egress make rc-live-gate`) is the 22nd mandatory gate and proves the privacy egress gate of ENT-13.1 ([ADR 0021](adr/0021-privacy-egress-gate.md)). It runs the real FastAPI application (OIDC with gate-owned keys, durable query accounting, query idempotency, the egress guard) on a gate-owned `ragops_test_privacy_<run>` PostgreSQL database migrated to head, with the real OpenAI and Azure OpenAI adapter classes driven by counting fake SDK clients; constructing a real SDK client counts as a paid call and is refused, so no request leaves the host. It checks default deny, policies that persist across application instances, tenant isolation of decisions and of the read-only administration view, exact purpose/provider/model/data-class matching, unclassified content, revocation (also between precheck and provider boundary, with the reservation released), that a denied primary is never rerouted and an unauthorized fallback never called, idempotent retry and replay, accounting without fabricated usage, append-only revisions and decisions, `store=false`, payload binding of permits, that a permit issued before a committed revocation starts no new request (dispatch check), the local-only demo workflow and complete cleanup. With this gate the release reports `22/22` and the security gate `33/33`.

**Release evidence aggregation (fail-closed).** `final-release-gate.json` never carries a status over from a previous summary. On every run `scripts/rc_live_gate.py` validates the evidence file of each of the 22 mandatory gates: it must name its gate, carry a valid status, a full `tested_commit` equal to `HEAD` and a timezone-aware timestamp that is neither in the future (5 minutes skew) nor older than the commit or 24 hours (the security gate's rules). Missing or stale evidence is `BLOCKED` (the gate has to run on this commit); malformed evidence, a foreign gate name, a future timestamp or a gate whose exit code contradicts its evidence (exit 0 without `PASS`, or `PASS` with a non-zero exit) is `FAIL`. Before a selected gate runs, its evidence is replaced by a `BLOCKED` placeholder, so a crash never leaves an older `PASS` behind. Incremental runs on the same commit still aggregate, because every earlier result is re-validated from its own evidence. `evidence_validation` in the summary records status, reason, tested commit and basis per gate.

**Paid-provider evidence policy.** The `external_llm_provider` gate is the only gate that calls a paid provider. Its evidence is produced on explicit operator authorization only and is not re-run for milestones that do not change the provider path. Its last result is `PASS` on `d9690cb` (2026-10-13); ENT-13.1 changed `src/ragops/llm/providers.py` and added `src/ragops/privacy`, so that result is no longer eligible and the release stays `BLOCKED` until a fresh, separately authorized run on the release commit (synthetic probe only, see ADR 0021). It is the single exception to the commit binding above (basis `historical_exception`): its evidence counts for a later commit only if it is a `PASS` with one executed request and a valid response, its `tested_commit` is an ancestor of `HEAD`, and `src/ragops/llm`, `src/ragops/modeling`, `src/ragops/privacy`, `scripts/external_llm_provider_gate.py`, `pyproject.toml` and `constraints.txt` are unchanged since that commit and in the worktree. Otherwise the gate is `BLOCKED` until an authorized paid run; the runner never starts one on its own. No security control binds this evidence file, and no other gate makes a paid call (`paid_provider_calls = 0` is required by every live control).
